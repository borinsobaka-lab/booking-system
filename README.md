# Запись на массаж — онлайн-запись + админка

Система онлайн-записи на услуги (массаж): витрина для клиентов и админка для
сотрудников. Фронтенд на React + Vite + TypeScript.

## Два режима хранения данных

- **Локальный** (по умолчанию, для разработки/демо): данные в браузере
  (`localStorage`). Ничего не публикуется, сервер не нужен.
- **Приватный бэкенд** (боевой): данные в **приватном** репозитории
  `booking-system-data` через **Cloudflare Worker** (`worker/`). Токен доступа
  живёт только на сервере; в публичном коде и браузерах его нет. Витрина получает
  только публичные данные (услуги, специалисты, занятость по времени — **без**
  имён, телефонов и почт), полные данные с контактами — только авторизованным
  сотрудникам. Настройка: **[worker/SETUP.md](worker/SETUP.md)**.

Режим переключается переменной сборки `VITE_API_BASE` (адрес Worker). Пусто ⇒
локальный режим. Слой данных изолирован (`src/db.ts`, `src/remote.ts`).

## Что уже есть

### Админка (`#/admin-panel` — отдельный адрес)
Вход для сотрудников доступен только по этому адресу и **нигде не связан
ссылками** из клиентской витрины (никаких кнопок «войти как сотрудник»).

- **Только вход, без регистрации.** Саморегистрации/создания администратора из
  интерфейса нет. **Суперадминистратор заводится вручную**: в боевом (remote)
  режиме — скриптом `worker/seed-owner.mjs` в приватный репозиторий; в локальном
  режиме для разработки/демо уже есть демо-владелец `demo` / `demo`.
- **Пользователи** (только для суперадминистратора): заведение
  **администраторов** и **сотрудников**, выдача им логинов и паролей (пароль
  показывается один раз, можно сгенерировать и скопировать), смена роли и
  пароля, удаление.
- **Роли и права**:
  - **Суперадминистратор** (`owner`) — всё: услуги, специалисты, записи, отзывы,
    клиенты, бренд, пользователи. Заводится вручную, он один.
  - **Администратор** (`admin`) — видит всё, **редактирует расписание** и
    полностью работает с записями: заводит вручную, отменяет, ставит отметки
    («оплачено массажисту», «по абонементу»). Услуги, специалистов, отзывы,
    бренд и учётки менять нельзя — это только у суперадминистратора.
  - **Сотрудник** (`staff`) — только просмотр. Если учётка привязана к карточке
    специалиста («Пользователи» → «Профиль мастера»), это **массажист**: он
    видит только свои записи, своих клиентов и свои выплаты; чужие записи
    сервер отдаёт ему обезличенно (только занятость времени — чтобы правильно
    считался общий кабинет). Письма о записях к другим мастерам ему не уходят.

  Роль меняется в разделе «Пользователи» (кнопка «Роль» у пользователя). Права
  проверяет сервер, а не браузер: в боевом режиме Worker принимает от
  администратора только расписание и действия с записями, а от сотрудника —
  ничего (403).
- **Услуги**: название, описание, длительность, стоимость, картинка.
- **Специалисты**: аватар, имя, фамилия, роль, список выполняемых услуг и своя
  ставка выплаты за сеанс (если отличается от общей). Специалистов может быть
  сколько угодно — расписание, записи и выплаты считаются по каждому.
- **Расписание** (суперадминистратор и администратор): у каждого специалиста
  свои рабочие дни и часы. «Рабочие дни и время на неделю» — отмечаете дни
  недели и задаёте время (и, если нужно, ежедневный перерыв) одним заходом;
  «Скопировать прошлую неделю» переносит уже заданное расписание вперёд;
  кнопка «＋ время» правит отдельный день. Мастера могут работать в один день —
  на таймлайне серым видно время, когда **общий кабинет** занят другим
  мастером.
- **Записи** (суперадминистратор и администратор): вкладки «Текущие»,
  «Прошедшие» (там же суммы выплат массажистам) и «Отмены», фильтр по мастеру.
  Здесь же можно создать запись вручную на любую дату, отменить существующую и
  поставить отметки («оплачено массажисту», «по абонементу»). Массажист в этом
  разделе видит только свои сеансы и свою сумму к получению. На карточке видно,
  какой это по счёту визит клиента и первый ли он у этого мастера: **клиента
  узнаём и по телефону, и по почте** — совпало хотя бы одно, значит визит уже
  не первый (записался с другого номера, но с той же почтой — тот же человек).
  Правило одно на весь раздел и на «Клиентов» — `src/clients.ts`.
- **Абонементы** (раздел виден всем сотрудникам, заводит и правит
  суперадминистратор или администратор): абонемент на N посещений привязывается
  к **телефону** клиента. Дальше всё считается само: записи этого клиента
  помечаются «по абонементу» и списывают визит (на витрине, при ручной записи в
  админке — везде), отменённая запись визит **возвращает**, а освободившийся
  визит достаётся ближайшей ещё не помеченной записи. Если абонемент завели,
  когда у клиента уже есть записи вперёд, они помечаются сразу — по порядку и
  ровно столько, сколько визитов в абонементе. Остаток не хранится отдельным
  счётчиком: потрачено = число подтверждённых записей по абонементу, поэтому
  баланс не может «уехать». Ручная отметка «по абонементу» в «Записях»
  остаётся: снятая вручную метка запоминается, и автоматика такую запись
  больше не трогает.
- **Общий кабинет**: в «Бренд» → «Запись» задаётся число массажных кабинетов
  (по умолчанию 1). Кабинет — общий ресурс: если он один, то при записи к
  одному массажисту это же время закрывается и у всех остальных — и на витрине,
  и при ручной записи в админке. Правило проверяет сервер, а не браузер.

### Витрина клиента (`#/`)
Баннер бренда (аватар, название, адрес) и три пути записи:
1. **Мастер** → услуга → дата и время.
2. **Выбрать дату** → время (только когда есть свободный специалист) → услуга →
   мастер (недоступные в это время — заблюрены).
3. **Выбрать услугу** → мастер → дата и время.

Доступны только реально свободные даты/времена; после выбора запись
**подтверждается автоматически** (симуляция). Email-уведомления и полноценная
регистрация брони — следующий этап.

**Телефон в форме записи** вводится не свободным текстом: слева стоит код
страны с круглым флагом (по умолчанию Грузия, `+995`), справа — номер по маске
этой страны. По клику на флаг открывается список всех стран с поиском: Грузия
первой, дальше по алфавиту на языке интерфейса (названия берутся у браузера,
`Intl.DisplayNames`). В запись номер уходит целиком — «+995 555 12 34 56».
Справочник стран с кодами и масками — `src/countries.ts`, флаги рисуются из
компактных описаний в `src/flags.tsx` (без картинок и внешних библиотек).

## Разработка

```bash
npm install
npm run dev        # http://localhost:5173/booking-system/  (локальный режим)
npm run build      # проверка типов + сборка в dist/
npm run test:e2e   # e2e-тесты Playwright

# Проверка бэкенда (Cloudflare Worker):
cd worker && node --test            # тесты логики API
cd worker && node mock-server.mjs  # локальный мок API (:8787)
```

Запуск фронтенда против локального мока API:
`VITE_API_BASE=http://localhost:8787 npm run dev`.

Приложение хэш-роутится: `#/` — витрина клиента, `#/admin-panel` — админка
(отдельный адрес, из витрины на неё нет ссылок).
